# 17. У сброса матча должен быть один смысл

Status: done
Type: task

## Зачем

Слово «сброс» пересекает шов `ReplaySink` и на другой стороне значит не то
же самое.

```ts
// server/utils/replay.ts — production: сброс молча
reset: () => matchState.reset()

// server/utils/ingest.ts — пустое тело: сброс с оповещением
matchState.reset()
wsService.broadcast({ type: 'idle' })
```

Интерфейс из двух методов дополнительно требует от вызывающего знать
порядок «сначала `reset`, потом `ingest`», и ничем этого не выражает.

Плюс третий сброс, скрытый: `matchState.ingest` на границе матча сбрасывает
себя сам (`match-state.ts:49`), тоже молча.

Итого три повода и три разных наблюдаемых исхода:

| Повод | Что делает сервер | Что видит оверлей |
| --- | --- | --- |
| Пустое тело GSI | сброс + `idle` | чистится сразу |
| Граница матча | сброс молча | приходит `state`; накопитель урона и след события остаются от прошлого матча |
| `load` / `seek` / `stop` записи | сброс молча | после `stop` и `load` рисует старый снапшот ещё 15 с, до таймаута живости |

Инвариант «как выглядит мир после сброса» не выражен нигде — отсюда и
расхождение.

## Что делаем

| Где | Что меняется |
| --- | --- |
| `server/utils/ingest.ts` | приватный `endMatch()`: сброс памяти и рассылка `idle` — всегда вместе |
| `server/utils/ingest.ts` | `isMatchBoundary` проверяется здесь: на границе `endMatch()`, затем обычный приём |
| `server/utils/match-state.ts` | скрытый самосброс на границе убирается |
| `server/utils/replay.ts` | `ReplaySink` сжимается до `{ ingest }`; приватный `resetMatch()` зовёт `sink.ingest({})` |
| `CONTEXT.md` | строка про `endMatch` |

### Жизненный цикл — в приёмном модуле, не в памяти матча

Рассматривалось: пусть `matchState.reset()` сам рассылает. Отвергнуто — это
затягивает транспорт в модуль памяти матча, ровно та связь, которую мы уже
отказались заводить в обратную сторону (`wsService.welcome`, тикет 16).
`matchState` сейчас тестируется без единого поддельного пира, и это стоит
сохранить.

### Шов сужается до одного метода

Сброс выражается `ingest({})` — тем же пустым телом, которым Dota сообщает о
конце матча и сессии. Остановка воспроизведения этим и является. Перемотка
становится просто двумя `ingest` подряд, и порядок перестаёт быть устным
договором.

Двух реализаций слова «сброс» больше нет, потому что слова нет.

### Имя возвращается внутрь реализации

`sink.ingest({})` в `stop()` нечитаем, поэтому внутри плеера заводится
приватный

```ts
/** Сброс состояния матча. Пустое тело — то же, чем Dota сообщает о конце матча. */
function resetMatch() {
  sink.ingest({})
}
```

Именно приватный, а не метод интерфейса: вернуть `reset` в `ReplaySink`
значило бы воссоздать возможность, ради устранения которой всё и делается —
два адаптера снова смогли бы разойтись в том, что такое «сброс». Глубина
есть свойство интерфейса, а не реализации: имя нужно там, где его читают, и
опасно там, где его пересекают.

### Один владелец правила границы

Проверка границы уходит из `matchState.ingest` совсем, а не дублируется «на
всякий случай». Два владельца одного правила — та же болезнь этажом ниже.
Звать `matchState.ingest` мимо `ingestRawBody` в production некому.

Побочно `matchState.ingest` теряет скрытый побочный эффект и становится
честно «диффит и взвешивает».

### Клиенту сообщаем `idle`, а не новый вид сообщения

Различать «матч кончился» и «начался другой» клиенту не нужно: в обоих
случаях он обязан забыть прошлое, а что началось новое, узнает следующим же
`state`. Ценность протокола из четырёх видов сообщений — в его узости.

## Тесты

Уровни не сращиваем. `test/replay.test.ts` остаётся про темп и управление с
изолированным sink — он теперь считает пустые тела среди принятых, а не
вызовы собственного счётчика. Наблюдаемый результат утверждается в
`test/ingest.test.ts`, где уже есть `collectBroadcasts()`.

Тест границы из `test/match-state.test.ts:83` переселяется туда же: после
снятия самосброса в прежнем месте утверждение станет ложным.

Подставлять production-sink в тесты плеера отвергнуто: `ReplaySink` затем и
вынесен наружу, чтобы тест на паузы не тащил за собой весь вывод событий.
Слепота лечится не сращиванием уровней, а появлением утверждения там, где
его не было.

## Что НЕ делаем

- **`IngestResult` не сужаем** — другой шов, другая работа.
- **ADR не заводим.** ADR-0002 уже описывает, что память матча живёт на
  сервере; наблюдаемость сброса — её следствие. Живой альтернативы здесь
  нет, а ADR без спора разбавляет папку, из-за чего её перестают читать.

## Приёмка

1. `test/ingest.test.ts`: граница матча рассылает `idle`, затем `state`;
   свежесть после границы как в начале.
2. `test/replay.test.ts`: `stop` и `load` подают пустое тело.
3. `npm run typecheck`, `npx vitest run`, `npx eslint app/ shared/ server/ test/`.
4. В браузере при ОТКРЫТОЙ панели: после `stop` записи пульт чистится
   сразу, а не через 15 секунд.
