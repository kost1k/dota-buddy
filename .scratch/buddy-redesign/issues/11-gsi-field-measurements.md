# 11. Замеры на игровом ПК

Status: ready-for-human
Type: research
Blocked by: 10

## Зачем

Два вопроса из первой разведки не закрыть иначе как живым матчем, и от
первого зависит, возможен ли таймер Рошана в принципе.

## Что сделать

1. Запустить бот-матч с включённой записью (тикет 10).
2. **Доходит ли блок `events` до обычного игрока?** В захваченных фикстурах
   он не разделён на playing и spectating, так что это неизвестно.
3. **Какова реальная задержка «событие в игре → POST»?** Ни одного
   первичного измерения не найдено. Мерить по `provider.timestamp` и
   `map.clock_time` против времени приёма на сервере.
4. Заодно: даёт ли `fpsLimit = 12` во сне реальные 12 кадров — на машине
   разработки это не измеряется, панель браузера скрыта и `rAF` придушен.
5. Привезти запись на машину разработки.
6. **Обезличить запись** — обязательный шаг, до любого разбора и до того,
   как файл куда-либо поедет:

   ```bash
   npm run sanitize:recording -- recordings/session.jsonl
   ```

   Снимаются `steamid`, `accountid`, имя игрока, идентификатор матча и
   текст чата. Токен снимает сам рекордер, на записи.

7. **Сверить результат независимо.** Отчёт скрипта не считается проверкой:
   первая версия чистки отчиталась об успехе, оставив в файле сотню живых
   сообщений, — своими допущениями свою же работу не проверить. Нужны
   внешние команды:

   ```bash
   grep -c '<steamid из сырого файла>' recordings/session.sanitized.jsonl   # ждём 0
   grep -c '[а-яА-Я]' recordings/session.sanitized.jsonl                    # ждём 0, если чат был русский
   jq -c . recordings/session.sanitized.jsonl | wc -l                       # совпадает с числом строк
   ```

   И главное — прогнать разбор на сыром и очищенном файле и убедиться, что
   выводы совпадают: расхождение означает, что чистка задела содержательное.

8. Удалять сырой файл только ПОСЛЕ сверки: переснять матч нельзя.
