# 02. Каркас нового клиента

Status: ready-for-agent
Type: task

## Зачем

По спеке §7 клиент заменяется, а не эволюционирует: из логики прототипа
принятые решения переживают только подключение к WebSocket, idle-таймаут и
валидацию формы payload. Всё остальное построено вокруг выброшенной модели.

Этот тикет расчищает площадку и ставит каркас с правильными настройками
рендера, чтобы ошибки прототипа не переехали в новый код.

## Что сделать

1. Снести клиентскую часть прототипа: `app/app.vue`, `app/components/BuddyScene.vue`,
   `app/components/BuddyObject.vue`.
2. Поднять новый каркас: страница оверлея, подключение к WebSocket, состояние
   сна при отсутствии данных, одна сцена TresJS.
3. Клиент на TypeScript, с типами входящего payload.
4. Визуальные константы (цвета, размеры, тайминги) — в одном месте, не
   разбросаны по стилям.

## Критерий приёмки

Каркас поднимается, подключается к WS, уходит в сон по таймауту. Плюс — и это
главное в тикете — ни одна из ошибок прототипа не воспроизведена:

- [ ] **Одна сцена, один рендер.** В прототипе `BuddyScene` монтировался
      дважды.
- [ ] **Нет `power-preference="high-performance"`.** Это подсказка выбора GPU,
      а не приоритета: приоритета над Дотой не даёт, зато делает контекст
      первым кандидатом на потерю.
- [ ] **`getContext('webgl2'|'webgl')` проверяется на `null`.** В OBS 33
      (Chromium 150) убран программный фолбэк — без проверки оверлей просто не
      запустится.
- [ ] **Анимации считаются от `delta`, не от номера кадра.** `rAF` в browser
      source залочен на выходной клок OBS.
- [ ] **Backing store канваса маленький, растянут через CSS.** Отображаемый
      размер бесплатен, размер буфера — нет.
- [ ] **Рендер-луп гейтится вручную** в состоянии сна. OBS сам останавливает
      страницу только если источник вообще нигде не рендерится.
- [ ] **Не используются web API новее Chromium 127** (потолок OBS 31/32).
- [ ] Нет постоянно смонтированных полноэкранных слоёв.

## Comments

### Реализовано — 2026-09-19

Клиент прототипа снесён целиком, каркас поднят. Структура:

```
shared/affect.ts        чистый интегратор аффекта (без Vue и Nuxt)
shared/gsi-message.ts   типы и разбор входящего сообщения
shared/liveness.ts      признак сна по тишине
app/utils/theme.ts      визуальные константы + CSS-переменные
app/utils/webgl.ts      предполётная проверка контекста
app/composables/        useAffect, useOverlayLink
app/components/         BuddyStage (единственный канвас), BuddyCreature (заглушка)
app/pages/index.vue     оверлей
```

**Сверх текста тикета сделано два добавления.** Первое — состояние аффекта
(`shared/affect.ts` + `useAffect`): без него тикетам 03 и 04 некуда писать и
неоткуда читать, а 02 — единственный незаблокированный тикет. Второе —
тестовая обвязка (`vitest`, 42 теста) на инварианты: интегратор, разбор
payload, таймаут сна. Константы инерции намеренно не тестируются, они
калибруются на пульте.

Состояние на композаблах с `useState`, не на Pinia: devtools отключены в
`nuxt.config.ts`, состояние между страницами делить не нужно, зависимость не
окупается. При росте графа сторов на рубеже 2–3 переход дешёвый.

### Найдено при проверке на живой странице

**Прозрачность требует двух флагов, не одного.** `alpha` даёт буферу
альфа-канал, но очистка идёт с `clearAlpha = 1`, и канвас выходит **чёрным
квадратом поверх игры**. Нужен явный `:clear-alpha="0"`. Обнаружено
скриншотом; в коде зафиксировано комментарием, потому что по названию props
это неочевидно.

### Проверено сквозным прогоном

Синтетический снапшот через `POST /api/gsi` прошёл санитизацию, ушёл в
WebSocket, разобрался на клиенте и лёг в состояние без искажений. `dpr = 1`
подтверждён: при `devicePixelRatio = 2` буфер остался 220×220.

### Не проверено здесь — вынести на игровой ПК

**Поведение `fpsLimit` в состоянии сна.** Панель браузера на машине
разработки скрыта, `document.visibilityState === 'hidden'`, и Chromium душит
`rAF` до ~1 Гц, а при полном скрытии — до нуля. Измерить реальную частоту
кадров в таких условиях невозможно.

Побочно выяснено полезное: цикл TresJS использует `THREE.Timer`,
подключённый к Page Visibility API, — при скрытии он останавливается и при
возврате не выдаёт накопленный провал одним куском. Поэтому дельту берём из
цикла, а не из собственного `performance.now()`.

Проверить на рубеже 0 или 4 вместе с приёмкой альфы.

### Якорь подобран по кадру — 2026-09-19

Проверка на игровом ПК показала, что бадди стоял слишком низко и мелко:
силуэт ~92 px по высоте (8.5% кадра), низ на `y≈873` при верхе панели
тайника `y≈878` — то есть впритык к HUD.

Подбирал на живом оверлее поверх настоящего кадра игры (скриншот как
подложка под работающей страницей), три варианта в пересчёте на 1920x1080:

| | сцена | высота силуэта | центр Y |
| --- | ---: | ---: | ---: |
| было | 220 | 92 | 825 |
| A | 280 | 118 | 730 |
| **B (принят)** | **320** | **135** | **650** |
| C | 380 | 160 | 550 |

C отклонён: поднимает бадди на середину экрана по вертикали, где идёт игра.
На пустом углу карты это незаметно, в реальном матче — начнёт спорить с
происходящим. A отклонён: почти не решает задачу, силуэт остаётся вплотную
к панели тайника.

Известная оговорка по B: нижний край силуэта на `y≈718`, а около `y≈706`
всплывают субтитры голосовых команд. Пересечение редкое и кратковременное.

Отступы якоря заодно перенесены из CSS страницы в `theme.ts`: в `index.vue`
они были зашиты, что нарушало требование этого же тикета — визуальные
константы в одном месте.
