# 02. Каркас нового клиента

Status: ready-for-agent
Type: task

## Зачем

По спеке §7 клиент заменяется, а не эволюционирует: из логики прототипа
принятые решения переживают только подключение к WebSocket, idle-таймаут и
валидацию формы payload. Всё остальное построено вокруг выброшенной модели.

Этот тикет расчищает площадку и ставит каркас с правильными настройками
рендера, чтобы ошибки прототипа не переехали в новый код.

## Что сделать

1. Снести клиентскую часть прототипа: `app/app.vue`, `app/components/BuddyScene.vue`,
   `app/components/BuddyObject.vue`.
2. Поднять новый каркас: страница оверлея, подключение к WebSocket, состояние
   сна при отсутствии данных, одна сцена TresJS.
3. Клиент на TypeScript, с типами входящего payload.
4. Визуальные константы (цвета, размеры, тайминги) — в одном месте, не
   разбросаны по стилям.

## Критерий приёмки

Каркас поднимается, подключается к WS, уходит в сон по таймауту. Плюс — и это
главное в тикете — ни одна из ошибок прототипа не воспроизведена:

- [ ] **Одна сцена, один рендер.** В прототипе `BuddyScene` монтировался
      дважды.
- [ ] **Нет `power-preference="high-performance"`.** Это подсказка выбора GPU,
      а не приоритета: приоритета над Дотой не даёт, зато делает контекст
      первым кандидатом на потерю.
- [ ] **`getContext('webgl2'|'webgl')` проверяется на `null`.** В OBS 33
      (Chromium 150) убран программный фолбэк — без проверки оверлей просто не
      запустится.
- [ ] **Анимации считаются от `delta`, не от номера кадра.** `rAF` в browser
      source залочен на выходной клок OBS.
- [ ] **Backing store канваса маленький, растянут через CSS.** Отображаемый
      размер бесплатен, размер буфера — нет.
- [ ] **Рендер-луп гейтится вручную** в состоянии сна. OBS сам останавливает
      страницу только если источник вообще нигде не рендерится.
- [ ] **Не используются web API новее Chromium 127** (потолок OBS 31/32).
- [ ] Нет постоянно смонтированных полноэкранных слоёв.
