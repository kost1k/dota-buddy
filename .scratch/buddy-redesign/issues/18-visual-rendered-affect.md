# 18. Шов отдаёт визуалу отображаемый аффект, а не сырьё

Status: done
Type: task

## Зачем

Контракт визуала несёт данные, а не поведение. Правило «отображаемый аффект
= зажатая сумма состояния и импульса, приглушённая сном, плюс цвет» —
соглашение, а не интерфейс, и потому скопировано пять раз:

```ts
const { valence, arousal } = clampAffect({
  valence: props.valence + props.impulse.valence,
  arousal: props.arousal + props.impulse.arousal,
})
const sleepy = asleep ? 0.25 : 1
tint.set(toHex(bodyColor(valence, arousal)))
```

`VisualEye.vue:48`, `VisualCrystal.vue:47`, `VisualSupershape.vue:32`,
`VisualTorus.vue:80`, `VisualMetaballs.vue:44`. Супершейп вдобавок делает то
же самое в `computed` и красит декларативно — то есть пятая копия ещё и не
совпадает по форме с остальными.

Цена соглашения: шестой визуал напишет своё, а шов этого не заметит. Само
ядро контракта при этом не покрыто тестом — у `shared/visual.ts` тестового
файла нет вовсе.

## Что делаем

| Где | Что |
| --- | --- |
| `shared/visual.ts` | `renderAffect({ state, impulse, asleep })` → `RenderedAffect { affect, sleepy, tint }` |
| `shared/visual.ts` | `VisualProps`: `valence`, `arousal`, `asleep` → `affect`, `sleepy`, `tint` |
| `app/components/BuddyStage.vue` | зовёт `renderAffect` одним `computed` |
| пять визуалов | читают готовое, преамбула исчезает |
| `test/visual.test.ts` | новый |
| `CONTEXT.md` | строка про `renderedAffect` |

### Считает сцена, а не визуал

Рассматривалась общая функция, которую зовёт сам визуал. Отвергнуто: пять
копий заменились бы одной, но правило осталось бы соглашением — визуал волен
её не звать. Когда сумма приходит готовой, складывать нечего.

Функция при этом всё равно живёт в `shared/` и проверяется в node — просто
зовут её этажом выше.

### Ширина контракта не растёт

`valence`, `arousal`, `asleep` уходят; `affect`, `sleepy`, `tint` приходят.
Семь полей было, семь осталось — а пять копий правила исчезли.

### Дыхание в кадр НЕ входит

Оно только выглядит общим. Кристалл и супершейп крутят им масштаб, глаз —
позицию, метасферы — разброс долей и с другим множителем (`0.1` против
`0.07`). Общая у них лишь частота, а она и так одна строка из
`shared/motion`. Класть в контракт то, что каждый применяет по-своему, —
ширина без рычага.

### Ярусные поля остаются в общем контракте

`event`, `milestones` и `level` читает один визуал из пяти, и это намеренное
решение о ярусах поддержки (спека §2.6). Тест удалением: вынести их — значит
завести в `BuddyStage` особый случай для кольца. Сложность переедет, а не
сконцентрируется, и переедет в худшее место. Четыре визуала за
неиспользуемые поля не платят ничем, кроме строчки в типе, — а это ровно та
цена, которую контракт обязан брать, чтобы пятый визуал стоил как первый.

### Моторика остаётся у визуала и остаётся гибкой

Базовая амплитуда дыхания у кольца `0.025`, у кристалла и супершейпа `0.02`.
Это не дрейф копипасты: кольцо родилось с `0.025` (751c753), а общая правка
1363eb9 свела `0.08` к `0.07` и базу не тронула.

Важнее другое: настроен пока ТОЛЬКО торус. У остальных четырёх сейчас лишь
базовое состояние, их числа ещё будут меняться по мере проверок. Поэтому
унификация моторики не просто не нужна — она вредна, и это записано в
документации контракта, где возникает соблазн, плюс строкой у `0.025` в
кольце, где расхождение видно.

### `asleep` уходит, остаётся `sleepy`

Все пятеро используют сон только как множитель. Флаг может понадобиться
позже — «во сне глаз закрывается» правка вероятная, — но вернуть поле
дешевле, чем удалять неиспользуемое: `sleepy` выводится из `asleep`, обратно
нет. Держать поле «на случай» — то, за что в тикете 17 срезан `reset` у
`ReplaySink`.
