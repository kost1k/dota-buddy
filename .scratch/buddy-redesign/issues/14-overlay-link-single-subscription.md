# 14. Связь оверлея владеет своим транспортом

Status: ready-for-agent
Type: task

## Зачем

Интерфейс `useOverlayLink` содержит невысказанный инвариант «зови меня один
раз». Внутри `if (import.meta.client)` каждый вызов строит собственный
`useWebSocket` и собственный `watch(data)`, а дедупликации по URL у VueUse
нет. Вызовов четыре:

| Где | Зачем |
| --- | --- |
| `app/pages/index.vue:8` | `awake` для режима сна |
| `app/pages/panel.vue:65` | `snapshot` и `awake` |
| `app/components/BuddyStage.vue:37` | `snapshot` для вех и уровня |
| `app/composables/useSnapshotSender.ts:32` | `snapshot` для подхвата состояния |

`snapshot` и `lastMessageAt` лежат в `useState` и потому общие, а
`previousSnapshot`, `previousAt` и `accumulatedDamage` — в замыкании, то есть
по экземпляру. `useAffect.addOffset` и `addImpulse` складывают по построению,
значит N подписок дают N применений одного события.

### Измерено до правки

Dev-сервер, одна вкладка, `GET /api/health`:

| Страница | `wsPeers` |
| --- | --- |
| Оверлей `/` | 2 |
| Пульт `/panel` | 3 |

Лог сервера подтверждает: три подряд `[ws] client connected` на открытие
пульта, три `disconnected` на уход.

Числовой замер. Пустой снапшот, затем тот же с уровнем на единицу больше —
серверное событие `levelUp` (амплитуда 0.3, направление валентности 0.5).
Цель валентности на пульте: **0.227**.

- одиночное применение: `0.5 × 0.3 × 0.55 = 0.0825`;
- тройное: `0.2475`, с затуханием за ~2 с при `OFFSET_TAU = 25` → `0.2285`.

То есть калибровка на пульте систематически завышена втрое — а пульт здесь
единственный способ калибровать.

### Попутный дефект в тех же строках

```ts
// useOverlayLink.ts:24 — «Секундный таймер, а не rAF: ... лишний кадровый
// таймер — нужен ещё меньше.»
const now = useTimestamp({ interval: 1000 })
```

В VueUse 15 `UseTimestampOptions` — это `{ controls, offset, callback }` плюс
`ConfigurableScheduler`. Поля `interval` больше нет, а реализация начинается с
`const { scheduler = useRafFn } = options`. Опция игнорируется молча, таймер
кадровый — ровно то, что комментарий над ним обещает не делать. И он тоже
размножен по числу вызовов.

## Что делаем

### Конструкция

| Слой | Чем владеет |
| --- | --- |
| `app/plugins/overlay-link.client.ts` | время жизни: один сокет, одна подписка, один таймер живости. Единственный писатель в `useState` |
| `shared/overlay-link.ts` | содержание: `reduceOverlayMessage(state, message, now) → { state, effects }`, чистая функция |
| `app/composables/useOverlayLink.ts` | чтение: `{ snapshot, awake }` над теми же ключами, без `import.meta.client` |

Транспорт и диспетчеризация — **один** модуль. Применить сообщение надо ровно
один раз, а гарантирует это единственность подписки; разнесение по двум
модулям вернуло бы вопрос «сколько подписчиков» на этаж выше.

Эффекты — **данные**, размеченное объединение (`base`, `react`). Тогда
«применено один раз» становится утверждением о длине списка, а не о числе
вызовов, и проверяется значением.

`previousSnapshot`, `previousAt` и `accumulatedDamage` переезжают из замыкания
в явное состояние редьюсера.

### Поведение при переподключении

`sync` принимает снапшот **как первый**: сбрасывает `previousSnapshot`,
`previousAt` и накопитель, затем принимает пришедшее.

Иначе после разрыва (`autoReconnect: true`) потеря здоровья считается против
снапшота, оставшегося до паузы: минута молчания и −60% здоровья придут одним
шагом как свежий урон. Запас за это время затухает почти в ноль, а разность
здоровья — нет.

Это тот же принцип, что уже принят на сервере для перемотки записи
(`server/utils/replay.ts:200-216`): «смотрим отсюда», а не «досматриваем в
ускорении». Правило «`sync` не будит» сохраняется.

### Часы живости

`useIntervalFn` в плагине над собственным `useState<number>`, явно.
Комментарий привести в соответствие с кодом. Обёртку `useTimestamp` не
сохранять: модуль только что погорел на молча проигнорированной опции, и
вариант через `scheduler` снова ставит поведение в зависимость от опции,
семантику которой придётся сверять по исходникам.

## Почему `shared/`, а не `app/`

Перепись импортов: сервер не импортирует десять модулей из шестнадцати
(`affect`, `affect-signals`, `escalation`, `liveness`, `milestones`, `motion`,
`overlay-message`, `palette`, `shuffle-bag`, `visual`). То есть `shared/` в
этом проекте на практике значит не «общее между `app/` и `server/`», а «чистая
доменная логика, проверяемая в node». Ближайший родственник редьюсера —
`affect-signals.ts` — ровно такой же.

Побочно это значит, что тест берётся существующей конфигурацией: у vitest уже
`environment: 'node'`, `include: ['test/**/*.test.ts']` и алиас `#shared`.
Ни `@vue/test-utils`, ни `happy-dom` не нужны.

## Что НЕ делаем

- **`BuddyStage` не получает `snapshot` пропсом.** Связь пересекает каждый
  клиентский путь, и заставлять две страницы прокидывать её вручную — это
  размазывание, а не концентрация.
- **Постоянного лога числа подписок не заводим.** После плагина инвариант
  верен по построению, а лог в консоли источника — шум.
- **Инфраструктуру клиентских тестов не поднимаем.** Редьюсер даёт то же
  покрытие на уже стоящей конфигурации.

## Приёмка

1. Тест на `reduceOverlayMessage`: накопление урона по снапшотам, «`sync` не
   будит», сброс на `idle`, `sync` как первый снапшот, одно сообщение —
   один эффект применения.
2. `GET /api/health` при одной открытой вкладке: `wsPeers` = 1 и на оверлее,
   и на пульте.
3. Повтор числового замера: цель валентности после `levelUp` ≈ 0.08,
   а не 0.23.
