# Roadmap

Долгий горизонт: рубежи и постоянный техдолг. Работа, которая ведётся прямо
сейчас, живёт в `.scratch/<feature-slug>/` — строка отсюда переезжает туда,
когда её берут в работу, и отмечается здесь, когда приземляется.

Текущая работа: [`.scratch/buddy-redesign/`](../.scratch/buddy-redesign/spec.md)

---

## Что уже работает

Пайплайн приёма данных, который переживает редизайн без изменений в основе:

- [x] Nuxt 4 + Nitro, WebSocket endpoint `/ws`, broadcast-сервис
- [x] `POST /api/gsi` с валидацией и санитизацией payload
- [x] Защита shared secret (`NUXT_GSI_SECRET` / `auth.token`)
- [x] Idle при пустом или невалидном payload
- [x] `GET /api/health`, уровни логирования, структурированные логи
- [x] Runtime-конфигурация endpoint-ов

Клиентская часть переписывается целиком — см. спеку, §7.

## Отложено намеренно

Решения приняты, работа не ведётся. Причины — в спеке.

- **Звук.** Событийный слой уже нормализован, точка подключения появится
  бесплатно. Конкурирует с голосом стримера, делается последним.
- **Сводка сессии.** Требует персистентности. Эмоциональный тон исхода
  читается из последнего снапшота без хранилища.
- **Раздача другим стримерам.** Темы, пресеты, онбординг. Архитектура не
  мешает, но конфигурируемость — налог на каждую фичу.
- **Интерактив с чатом.** Отдельный продукт поверх этого.

## Переход на сетевую топологию

Сейчас тестирование идёт вариантом (a): репозиторий разворачивается на
игровом ПК, всё локально. Цель — приложение остаётся на машине разработки,
игровой ПК шлёт по локальной сети. Короткая петля «поправил здесь — увидел
там» без переноса кода.

- [ ] Сервер слушает не только loopback
- [ ] `NUXT_PUBLIC_WS_URL` на сетевой адрес
- [ ] `NUXT_GSI_SECRET` обязателен — трафик идёт по сети, а не внутри машины
- [ ] Описать обе топологии в README
